# 开源发布清单

按顺序做完就能推上 GitHub。每一条都对应一个真实会踩的坑，不是形式主义。

## 1. 发布前必须改的三处

| 位置 | 现在 | 改成 |
|---|---|---|
| `Cargo.toml` → `repository` | `https://github.com/yourname/MySnipTool` | 你的真实仓库地址 |
| `LICENSE` 第 3 行 | `Copyright (c) 2026 MySnipTool contributors` | 你的名字或 GitHub ID（也可以保留 "contributors"） |
| `README.md` / `README.zh-CN.md` 里的 `../../releases` | 相对链接，指向仓库 Releases | 不用改，但只有当仓库名是 `MySnipTool` 时才正确 |

改完 `repository` 之后跑一次 `cargo package --list` 看有没有不该发布的东西被带进去。

## 2. 隐私与体积

已经处理好的：

- `.gitignore` 排除了 `/target` 和 `.workbuddy/`（后者是我这边的开发记录，不属于项目）
- 源码、脚本、文档里**没有**硬编码的本地路径和用户名 —— 每次提交前再确认一遍：

```powershell
grep -rn "yuanci\|C:\\\\Users" --include="*.rs" --include="*.ps1" --include="*.md" . |
  Select-String -NotMatch "target|workbuddy"
```

可以斟酌的一项：`assets/icons/variants/` 有 412 KB 的设计探索稿（比整个 exe 还大）。
留着是设计来源的存档，删掉能让仓库更轻。要删就只留 `v1-round.png`（图标几何的原图）。

## 3. 首次推送

```powershell
git init -b main
git add -A
git status --short          # 确认没有 target/ 和 .workbuddy/
git commit -m "MySnipTool 1.0.0: 473 KB screenshot tool, pure Rust + Win32"
git remote add origin https://github.com/<你>/MySnipTool.git
git push -u origin main
git tag v1.0.0 && git push origin v1.0.0
```

推 tag 会触发 `.github/workflows/build.yml` 的发布任务，自动把 `sniptool.exe`
挂到 Release 上，用户不用装 Rust 也能下载。

## 4. 版本号要同步三个地方

`Cargo.toml` 的 `version`、`assets/app.rc` 里的 `FILEVERSION`/`VERSION`、
README 里引用的体积与行数。`build.rs` 不会自动把 `Cargo.toml` 的版本传给 `rc.exe`，
改版本时容易漏掉 `app.rc`，结果 exe 属性里还是旧版本。

## 5. 杀毒软件与 SmartScreen 的现实预期

这个程序同时做了四件被启发式高度关注的事：注册全局热键、抓屏、写剪贴板、
写 `HKCU\...\Run`。**这在功能上是必要的，在行为上就是和键盘记录器同构。**

必然发生的：

- 首次下载运行会出现 SmartScreen「Windows 已保护你的电脑」，需要用户点"仍要运行"。
  未签名二进制没有声誉，这无法通过代码解决。
- 少数引擎（尤其是国产安全软件的启发式）可能报"风险程序/行为拦截"，通常不是
  确认为病毒，而是"未知程序正在写启动项"这类提示。

可以做的（按性价比排序）：

1. **不要加壳**。本项目的 `opt-level="z" + LTO + strip` 已经让二进制没有明显的
   字符串，再上 UPX 会直接被一批引擎判为加壳木马。
2. **提供构建来源**：GitHub Actions 产出的 exe 带可追溯的构建日志，比"作者本机
   编译的上传"可信得多。上面的 workflow 已经做了这件事。
3. **误报就提交**。微软的提交入口是
   <https://www.microsoft.com/en-us/wdsi/filesubmission>，一般几天内解除；
   其它引擎各有自己的表单。README 里的 "Antivirus and SmartScreen" 一节已经
   提前把这件事讲清楚，能减少 issue 噪音。
4. **代码签名**。传统 OV 证书约 200 美元/年且要企业资质；Azure Trusted Signing
   是订阅制、便宜得多，但对个人开发者有历史要求。如果打算长期维护，值得办；
   只是发个 v1.0 玩票，不办也行。

## 6. 开源后一定会收到的 issue（提前想好怎么答）

| 问题 | 答案 |
|---|---|
| "为什么内存显示 0.34 MB，是不是假的？" | README 里已写明：`SetProcessWorkingSetSize` 只是把冷页移进 standby，私有提交是 2.1 MB。诚实回答比争辩有用。 |
| "能不能加标注/箭头/马赛克？" | V1 明确不做。这是唯一的体积与复杂度红线，一旦开就回不去。 |
| "Alt+A 被 QQ 占了" | 已有优雅降级（托盘菜单 + tooltip + 设置里改绑），指过去即可。 |
| "Win10 上圆角是硬的" | 预期行为，`DwmSetWindowAttribute` 在 Win10 不存在，退回 region。 |
| "多显示器不同缩放会错位" | 已知限制，写在 README 的 Limitations 里。这类贡献很适合让社区来提 PR。 |

## 7. 建议标注 "good first issue" 的三件事

1. `WM_DPICHANGED` 支持（设置窗口拖到不同缩放比例的显示器时重排）
2. 多显示器混合 DPI 下的遮罩坐标验证
3. 深色主题（现在只有浅色）

前两个是真缺陷，第三个是纯增量，都不会破坏现有架构。
